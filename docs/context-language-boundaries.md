# 上下文语言边界

0.3.0 的默认 `display-only` 模式把输出译文限定在界面：模型历史保留 Claude 原始回复，默认语言配置要求英文。它解决插件把中文译文重新送回 Claude 的问题，不承担完整身份匿名化或所有上下文翻译。

## 本轮已经处理

| 入口 | 行为 |
| --- | --- |
| 普通用户输入 | 按原有设置译成提示词语言，默认英文；代码、路径等受保护内容保留字面值 |
| Claude 回复的显示 | 只翻译实际可见的助手文本块；摘要和正文分别处理 |
| 模型响应与后续历史 | 保留原始消息、工具块、停止标记及错误，界面译文不追加到历史 |
| 无界面运行 | 默认保留原始回复，不调用输出翻译；显式 `conversation` 可恢复旧行为 |
| 清空、重载与恢复 | 清理旧显示任务；可见原文按需重译，译文缓存不额外持久化 |

建议保持 **Claude prompt language = en**、**Claude reply language = en / same-as-prompt**、**Output translation mode = display-only**。回复语言通过指令引导，模型仍可能输出引用、代码或其他语言的原始资料。

## 需要单独处理的入口

| 入口 | 当前范围 | 后续处理时需要保留的内容 |
| --- | --- | --- |
| CLAUDE.md、记忆、项目指令 | 不自动翻译或删除 | 指令层级、要求的原意及代码示例；修改语言偏好需要明确决定 |
| Skill 自动发现说明 | 不统一翻译，说明可能进入上下文 | 名称、调用标识、触发条件和权限语义 |
| 调用后的 Skill 正文 | 不自动翻译 | 代码、参数、动态展开结果及指令含义；原生 `skill.prompt` 是可评估的入口 |
| 文件读取、Bash、MCP 和其他工具结果 | 不改写 | 源码、错误原文、结构化字段、字面量和可复现证据，不能统一当自然语言翻译 |
| 图片、截图、附件 | 不做 OCR 或替换 | 文字、图形及二进制内容；英文提示词不能改变图片中的中文 |
| 路径、URL、标识符、代码及引用 | 保留字面值 | 中文名称可能仍可见；翻译会破坏可执行内容或引用准确性 |
| 其他插件、Slash 命令和系统提醒 | 不统一拦截 | 工具协议、来源与安全边界，需逐项确认可改写范围 |
| 子代理的提示词与内部上下文 | 不统一翻译 | 各自的系统指令、预加载 Skill 和工具结果；界面翻译不改变它们的历史 |
| 旧会话中已有的中文 | 不自动删除或改写 | 原始会话记录；可开始新会话验证新的历史行为 |

Skill 描述通常参与自动发现，调用后的正文也会进入上下文，详见 [Claude Code 官方 Skill 说明](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)。本插件没有附带 `SKILL.md`，自己的插件和 hooks 简介使用通用英文描述；配置页的语言默认值属于配置元数据，主动读取文件时仍然可见。

## 语言与含义

把“请用中文回答”翻译为 `Reply in Chinese`，仍会透露中文偏好。国籍、城市、名字和其他身份信息也不会因为句子变成英文而自动消失。要进一步减少这类线索，需要单独审查内容含义，而不是只检测是否含汉字。

本轮没有修改全局设置、用户指令文件、已有 Skill 或工具输出。若启用旧的 `conversation` 模式，输出译文仍会写回历史。

## 显示层的实际限制

- 纯代码及代码边界不完整的可见块保持原文，避免误译跨块代码。特别大的文本块或超出显示缓存容量的内容会提示，原始历史不受影响。
- 同一可见文本块的重绘复用缓存；重载、恢复或缓存淘汰后可能重新调用翻译后端。
- 离屏、正文清空或会话结束会撤销排队任务并忽略过期结果；已启动的后端调用可能继续运行到完成或宿主超时，期间仍计入并发上限。
- 界面翻译失败可按按钮重试；宿主拒绝渲染钩子或渲染失败时，可能恢复原始界面显示。这不把译文写入模型历史。
- 历史保持原文意味着保留 Claude 实际生成的内容，不保证所有原文都严格为英文，也不涉及服务端账号、网络或地域信息的处理。
